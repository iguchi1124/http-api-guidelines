# HTTP API Guidelines

作業前に[HTTP API開発ガイドライン](references/http-api-guidelines.md)を読む。この参照ファイルを規約本文の唯一の編集元とする。

- 本文の確定事項を設計・実装・OpenAPIに反映する。
- カスタムアクションにはPOSTまたはQUERYを使用できる。QUERYは安全かつ冪等な照会・計算に使用し、状態変更を要求する操作にはPOSTを使用する。
- 「未決定事項」を必須ルールとして補完しない。既存規約を確認し、新しい判断が必要なら理由を明示する。
- オブジェクトは原則として用途別のルートキーで包む。名前はエンドポイントごとに選び、OpenAPIで固定する。dataなど特定の共通名を要求しない。
- アプリケーションが定義するJSONキーは、ルートキー・入れ子・付加情報・Problem Detailsの拡張メンバーを含めsnake_caseに統一する。
- エラー系のProblem Detailsには正常系のラップ規約を適用しない。
- リンクやページングのキーを一律に要求しない。個別のAPI契約と共通規約を区別する。
- レビューでは、該当箇所・根拠となる規約・修正案を示す。提案を規約違反と呼ばない。
- 既存APIの互換性を確認し、依頼範囲の実装と仕様を整合させる。無関係なAPIの一括移行やツール設定変更は行わない。

このスキルはSKILL.mdとreferences内の文書だけで利用できる。配布元リポジトリのAGENTS.md・CLAUDE.mdを編集するときは、同等の指示と参照先を整合させる。
